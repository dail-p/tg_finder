# Telegram Bot с поиском инструкций по каналам - Исследование архитектур

## Требования к боту

1. **Ответы на вопросы** - поиск информации по тематике канала, собранной из разных постов
2. **Пачки каналов** - группировка каналов для поиска (например, новостные каналы)
3. **Обработка отсутствия информации** - корректный ответ когда данных нет
4. **Структурированные ответы** - не просто вывод постов, а конкретные ответы с ссылками на источник

---

## Архитектурные варианты

### Вариант 1: RAG (Retrieval-Augmented Generation)

**Компоненты:**
- Telegram Bot API (aiogram)
- Векторная БД (pgvector/Chroma) для хранения эмбеддингов постов
- LLM для генерации ответов (OpenAI API/локальная модель)
- Периодический парсер каналов (cron/scheduler)

**Поток:**
1. Парсер собирает посты из каналов → токенизирует → создаёт эмбеддинги → сохраняет в векторную БД
2. Пользователь задаёт вопрос
3. Бот формирует эмбеддинг запроса, ищет похожие посты
4. LLM генерирует ответ на основе найденных фрагментов с цитатами

**Плюсы:** Качественные ответы, семантический поиск, быстрое MVP
**Минусы:** Галлюцинации, плохо ищет имена/даты, зависимость от внешних API

---

### Вариант 2: Keyword-based с BM25

**Компоненты:**
- Telegram Bot API
- OpenSearch/PostgreSQL FTS5 для полнотекстового поиска
- Периодический парсер каналов

**Поток:**
1. Парсер индексирует посты в поисковик
2. Пользователь задаёт вопрос
3. Бот ищет по ключевым словам, ранжирует результаты BM25
4. Формирует ответ из релевантных фрагментов

**Плюсы:** Точность для exact matches, контролируемый threshold, низкий риск галлюцинаций, дешево
**Минусы:** Не понимает смысл, проблемы с синонимами, хуже семантика

---

### Вариант 3: Hybrid (BM25 + Vector + Reranker)

**Компоненты:**
- Telegram Bot API
- BM25-индекс (PostgreSQL FTS5/OpenSearch)
- Векторная БД (pgvector/Chroma)
- Reranker модель
- LLM для синтеза ответов

**Поток:**
1. Query → [BM25 + Vector] параллельный поиск
2. RRF (Reciprocal Rank Fusion) объединение результатов
3. Reranker переранжирует
4. LLM генерирует ответ

**Плюсы:** Точность + семантика, снижает false positives, работает с именами и понятиями
**Минусы:** Сложнее инфраструктура, дороже, медленнее

---

### Вариант 4: Гибрид с ручным уточнением

**Компоненты:**
- Telegram Bot API
- Гибридный поиск (BM25 + Vector)
- Confidence scoring
- История диалогов

**Поток:**
1. Query → Confidence check
2. High confidence: Hybrid search → LLM answer
3. Low confidence: Уточнение у пользователя
4. Very low: "Не могу найти информацию"

**Плюсы:** Минимизирует галлюцинации, лучше UX для сложных запросов
**Минусы:** Медленнее, сложнее логика

## Рекомендуемый план разработки (для субагентов)

### Этап 1: MVP (RAG)
1. Настроить Telegram Bot API (aiogram)
2. Реализовать парсер каналов (Telethon/Telegram API)
3. Настроить векторное хранилище (pgvector/Chroma)
4. Интегрировать LLM API (OpenAI)
5. Базовые команды /search, /help

### Этап 2: Группы каналов
6. CRUD для групп каналов (/create_group, /add_to_group, /my_groups)
7. Фильтрация поиска по выбранным группам

### Этап 3: Hybrid улучшения
8. Добавить BM25-индекс (PostgreSQL FTS5)
9. RRF-слияние результатов
10. Reranker для повышения точности

### Этап 4: Confidence scoring
11. Оценка уверенности в ответе
12. Интерактивное уточнение при низкой уверенности
13. Обработка "нет информации"

### Технологический стек
- **Python 3.12 + aiogram** - асинхронный Telegram фреймворк
- **PostgreSQL + pgvector + FTS5** - гибридное хранилище
- **OpenAI API** - для эмбеддингов и LLM
- **Telethon** - для парсинга каналов
- **AsyncIOScheduler** - для периодического парсинга

---

## Рекомендация

**Гибридный подход с BM25 + Vector** — оптимальный баланс для Telegram-контента с короткими постами. BM25 находит имена и даты, vector — смысл, reranker повышает точность. Для MVP можно начать с RAG, затем добавить BM25-индексацию.
